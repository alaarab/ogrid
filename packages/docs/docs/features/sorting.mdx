# Sorting

Click a column header to sort. Click again to reverse. **Shift+click** another header to sort by it as well. Use **Clear sort** in the column menu to remove it. An arrow shows the current direction. That's the whole interaction — no configuration beyond `sortable: true`.

The column menu (⋮) has the same actions for keyboard users: **Sort ascending**, **Sort descending**, **Clear sort**, and **Add to sort**.

## Make a column sortable

Add `sortable: true` to any column definition:

<Tabs groupId="framework">
  <TabItem value="react" label="React" default>

```tsx
import { OGrid } from '@alaarab/ogrid-react-radix';

const columns = [
  { columnId: 'name', name: 'Name', sortable: true },
  { columnId: 'age', name: 'Age', sortable: true, type: 'numeric' as const },
  { columnId: 'department', name: 'Department', sortable: true },
  {
    columnId: 'salary',
    name: 'Salary',
    sortable: true,
    type: 'numeric' as const,
    valueFormatter: (v) => `$${Number(v).toLocaleString()}`,
  },
];

function App() {
  return (
    <OGrid
      columns={columns}
      data={people}
      getRowId={(item) => item.id}
      defaultPageSize={10}
    />
  );
}
```

## Set a default sort

Use `defaultSortBy` and `defaultSortDirection` to pre-sort the grid on mount — useful when there's an obvious "right" order for your data, like newest-first for a log or alphabetical for a directory:

```tsx
<OGrid
  columns={columns}
  data={employees}
  getRowId={(item) => item.id}
  defaultSortBy="name"
  defaultSortDirection="asc"
/>
```

## Sort by several columns

Sort by one column, then **Shift+click** another header (or pick **Add to sort** in its column menu) to break ties with it. Each sorted header shows its arrow and a small priority number: 1 for the primary sort, 2 for the next, and so on. Shift+click a sorted column again to flip its direction, and a third time to remove it from the sort. A plain click on any header goes back to sorting by that one column, the same as Excel and AG Grid.

<MultiSortDemo />

Rows that tie on every level keep their original order (the sort is stable). Every level honors the column's `type` and custom `compare`, and the Web Worker path (`workerSort`) sorts by all levels too. A `compare` on any level keeps that sort on the main thread.

Start with several levels using `defaultSortModel`, or control them with `sortModel` and `onSortModelChange`:

```tsx
const [sortModel, setSortModel] = useState<ISortModelItem[]>([
  { field: 'department', direction: 'asc' },
  { field: 'salary', direction: 'desc' },
]);

<OGrid
  columns={columns}
  data={people}
  getRowId={(item) => item.id}
  sortModel={sortModel}
  onSortModelChange={setSortModel}
/>
```

`sortModel` takes precedence over `sort`. The single-level API keeps working unchanged: `sort`/`onSortChange` describe the primary level, so existing code doesn't need to change. To keep a secondary level when you control sorting, use `sortModel`; a controlled `sort` holds one level only.

With `useHeadlessGrid`, call `toggleSort(columnId, { additive: event.shiftKey })` from your header and read `sortModel` and `sortPriority(columnId)`.

## Custom sort order

By default, text columns sort alphabetically and numeric columns sort numerically. When that isn't right — priority levels, custom status orderings, anything domain-specific — provide a `compare` function:

```tsx
const columns = [
  {
    columnId: 'priority',
    name: 'Priority',
    sortable: true,
    // "High" should sort before "Medium" which sorts before "Low"
    compare: (a, b) => {
      const order = { High: 0, Medium: 1, Low: 2 };
      return order[a.priority] - order[b.priority];
    },
  },
  {
    columnId: 'status',
    name: 'Status',
    sortable: true,
    // Custom business logic: "In Progress" first, then "Open", then "Closed"
    compare: (a, b) => {
      const order = { 'In Progress': 0, Open: 1, Closed: 2 };
      return (order[a.status] ?? 99) - (order[b.status] ?? 99);
    },
  },
];
```

:::tip Pro tip
Custom `compare` functions receive the full row objects — not just the cell values. That means you can sort by computed values, nested fields, or anything else you can derive from the row.
:::

## Keep sort state in your app

If you need to sync sort state to the URL, read it from an API, or share it between components, use controlled mode:

```tsx
function App() {
  const [sort, setSort] = useState({ field: 'name', direction: 'asc' as const });

  // Persist to URL:
  // useEffect(() => { setSearchParam('sort', sort.field); }, [sort]);

  return (
    <OGrid
      columns={columns}
      data={people}
      getRowId={(item) => item.id}
      sort={sort}
      onSortChange={setSort}
    />
  );
}
```

When `sort` and `onSortChange` are both present, the grid is fully controlled — it never manages sort state internally. For multi-level sorting, control `sortModel` and `onSortModelChange` instead (see above).

## Server-side sorting

Sending sort state to your API is straightforward. The grid passes sort info to `fetchPage()` — your server does the actual ordering:

```tsx
const dataSource: IDataSource<Project> = {
  fetchPage: async ({ sort, page, pageSize, filters }) => {
    const params = new URLSearchParams({
      page: String(page),
      pageSize: String(pageSize),
    });

    // Wire sort directly to your query params or request body
    if (sort) {
      params.set('sortBy', sort.field);
      params.set('sortDir', sort.direction);  // 'asc' | 'desc'
    }

    const res = await fetch(`/api/projects?${params}`);
    const json = await res.json();
    return { items: json.data, totalCount: json.total };
  },
};
```

For multi-level sorts, read `sortModel`: every level, primary first (`sort` is its first item). Windowed sources get the same `sortModel` in `getRows` and `getRowCount`:

```tsx
fetchPage: async ({ sortModel = [], page, pageSize, filters }) => {
  const orderBy = sortModel.map((s) => `${s.field} ${s.direction}`).join(', ');
  // ...ORDER BY department asc, salary desc
},
```

:::tip Pro tip
Server-side sorting disables client-side sort entirely — the grid just re-fetches when the user clicks a header. This pairs perfectly with large datasets where you never want all rows in the browser at once. See [Server-Side Data](./server-side-data) for the full setup.
:::

## Props reference

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `sortable` | `boolean` | `false` | Set on `IColumnDef`. Enables click-to-sort on that column header. |
| `compare` | `(a: T, b: T) => number` | — | Custom sort comparator on `IColumnDef`. Receives full row objects. |
| `sort` | `{ field: string; direction: 'asc' \| 'desc' }` | — | Controlled sort state on `OGrid`. |
| `onSortChange` | `(sort) => void` | — | Called when the user changes the sort. Required for controlled mode. |
| `defaultSortBy` | `string` | — | Initial sort column (uncontrolled only). |
| `defaultSortDirection` | `'asc' \| 'desc'` | `'asc'` | Initial sort direction (uncontrolled only). |
| `sortModel` | `ISortModelItem[]` | — | Controlled multi-level sort, primary first. Takes precedence over `sort`. |
| `onSortModelChange` | `(sortModel) => void` | — | Called with every level whenever the sort changes. |
| `defaultSortModel` | `ISortModelItem[]` | — | Initial multi-level sort (uncontrolled only). Takes precedence over `defaultSortBy`. |
